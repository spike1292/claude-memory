# Bun: evaluated and declined

**Date:** 2026-08-17 · **Bun:** 1.3.14 · **Node:** 24.19.0 · **Status:** declined, revisit only with new numbers

## Question

Would running the plugin on Bun instead of Node make it faster?

## Answer

No. Bun **cannot run this codebase**, and the measured upside where it could was ~20 ms per hook
spawn — less than half of what a change requiring no new runtime delivered the same day.

## The blocker

Not the native dependencies everyone expects:

| dependency | under Bun 1.3.14 |
| --- | --- |
| `onnxruntime-node` | loads fine |
| `@huggingface/transformers` | loads fine |
| **`node:sqlite`** | **does not exist** |

```
$ bun t.mjs
error: Could not resolve: "node:sqlite". Maybe you need to "bun install"?
```

Bun ships `bun:sqlite` with a different API. `node:sqlite`'s `DatabaseSync` is what
`scripts/memory-semantic.mjs` (the whole search engine) and `hooks/memory-recall.mjs` are built on.

Note `memory-recall.mjs` imports `DatabaseSync` at top level even though its happy path — the
resident socket server — never touches SQLite. So it fails under Bun immediately, not lazily.

Bun-clean today: `memory-audit-checks.mjs`, `distill-session.mjs`, `memory-eval.mjs`,
`memory-synth-vault.mjs`.

## The measurement

20 runs each, macOS arm64:

| path | node | bun | delta |
| --- | --- | --- | --- |
| bare script | 40 ms | 17 ms | −23 ms |
| `memory-audit-checks --check-file` | 48 ms | 30 ms | −18 ms |

Ceiling: **~20 ms per hook spawn**, and only on hooks Bun can actually run — which excludes both
hot paths (per-prompt recall, per-write validation... the latter until it stops needing the engine).

## Why declined

1. **It reintroduces a second runtime.** Python was removed on 2026-08-16 for precisely this: a
   second runtime is a second thing to be the wrong version on someone's machine, and it was —
   macOS ships Python 3.9, which silently broke session distillation. "But this one is faster"
   does not answer that argument.
2. **Unblocking the parts that matter needs a SQLite abstraction with two backends** — one
   interface, two implementations — in code whose failures are already silent by design.
3. **The CI matrix doubles**, for engines that diverge subtly (regex, `Intl`) in exactly the kind
   of code where divergence does not raise, it just returns a different answer.

## What was done instead

Profiling found `projectKey()` spending **72 ms** in-process on a bash+git subprocess — three times
Bun's saving — on every prompt and every file write. Caching it took a fresh-process lookup from
**98 ms → 49 ms**, with no new runtime.

See [shell vs node in hooks](2026-08-17-shell-vs-node-hooks.md) for where the remaining time goes.

## If you want to revisit

Bring numbers, and check `node:sqlite` first — that is the gate. Everything else in this document
is downstream of it.
